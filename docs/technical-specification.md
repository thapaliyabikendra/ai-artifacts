## **Clinic Management System — ABP Framework Implementation**

---

## **1. Architecture Overview (ABP Modular Architecture)**

Solution will use ABP’s standard modules:

* **Clinic.Domain**
* **Clinic.Application**
* **Clinic.Application.Contracts**
* **Clinic.EntityFrameworkCore**
* **Clinic.HttpApi**
* **Clinic.HttpApi.Host**

ABP will provide:

* Repositories & Unit of Work
* Permission & Authorization System
* Conventional controllers
* AutoMapper mapping
* Auditing, Soft Delete, Validation
* Identity + JWT Authentication

## **5. Application Services (Detailed)**

### **5.1 PatientAppService**

`CrudAppService<Patient, PatientDto, int, PagedAndSortedResultRequestDto, CreatePatientDto, UpdatePatientDto>`

Supports:

* Create
* Update
* Delete (soft)
* Get
* GetList (paging/filtering)

### **5.2 DoctorAppService** *(Admin only)*

Same CRUD service pattern.

### **5.3 AppointmentAppService**

Custom Application Service (not CRUD).

Methods:

* `CreateAsync(input)`
* `RescheduleAsync(id, newDate)`
* `CancelAsync(id)`
* `MarkCompletedAsync(id)`
* `GetDoctorAppointmentsAsync(doctorId, dateRange)`

### **5.4 DoctorScheduleAppService**

CRUD for schedules.

## **7. Data Validation Rules**

### Patient

* Email must be unique
* Phone format validation
* DOB cannot be future date

### Appointment

* Must fall within the doctor’s available schedule
* Cannot conflict with existing appointments
* Date must be future date

### Schedule

* EndTime > StartTime
* No overlapping schedules for same doctor+day
