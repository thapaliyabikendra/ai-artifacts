# Documentation Structure

> **Purpose**: Central documentation hub for the Clinic Management System.
> **Usage**: Agents read specific files based on their stage in the `/add-feature` workflow.

## Quick Reference by Stage

| Stage | Agent | Primary Docs | Secondary Docs |
|-------|-------|--------------|----------------|
| 1. Analyze & Require | `business-analyst` | `domain/*` | `architecture/README.md` |
| 2. Design | `backend-architect` | `architecture/README.md`, `domain/entities/` | `architecture/patterns.md`, `domain/permissions.md` |
| 3. Implementation | `abp-developer` | `architecture/README.md`, `architecture/patterns.md` | `domain/entities/` |
| 4. Testing | `qa-engineer` | `domain/business-rules.md`, `architecture/patterns.md` | Feature docs |
| 5. Code Review | `code-reviewer` | `architecture/patterns.md` | Feature docs |
| 6. Security | `security-engineer` | `domain/permissions.md`, `domain/roles.md` | `architecture/README.md` |

## Directory Structure

```
docs/
├── README.md                    # This file - documentation hub
├── domain/                      # Business domain knowledge
│   ├── README.md               # Domain overview
│   ├── entities/               # Entity definitions (one file per entity)
│   │   ├── patient.md
│   │   ├── doctor.md
│   │   ├── appointment.md
│   │   └── doctor-schedule.md
│   ├── business-rules.md       # BR-XXX format rules
│   ├── roles.md                # User roles and capabilities
│   ├── permissions.md          # Permission structure
│   └── enums.md                # Enumeration definitions
├── architecture/               # Technical architecture
│   ├── README.md               # Architecture overview (project-context)
│   ├── patterns.md             # Code patterns and conventions
│   └── api-contracts.md        # API endpoint reference
├── features/                   # Feature-specific documentation
│   ├── _templates/             # Document templates
│   └── {feature-name}/         # Per-feature docs
│       ├── requirements.md
│       ├── technical-design.md
│       ├── test-cases.md
│       ├── review-report.md
│       └── security-audit.md
└── decisions/                  # Architecture Decision Records
    └── ADR-XXX-title.md
```

## File Purposes

### Domain Layer (`docs/domain/`)

Files describing **what** the system does from a business perspective.

| File | Purpose | Updated By |
|------|---------|------------|
| `README.md` | Domain overview, bounded contexts | business-analyst |
| `entities/*.md` | Entity definitions, relationships | business-analyst |
| `business-rules.md` | BR-XXX business rules | business-analyst |
| `roles.md` | User roles and capabilities | business-analyst |
| `permissions.md` | Permission definitions | business-analyst |
| `enums.md` | Enumeration definitions | business-analyst |

### Architecture Layer (`docs/architecture/`)

Files describing **how** the system is built technically.

| File | Purpose | Updated By |
|------|---------|------------|
| `README.md` | Project identity, paths, build commands | backend-architect |
| `patterns.md` | Coding patterns, naming conventions | backend-architect |
| `api-contracts.md` | API endpoints, methods | backend-architect |

### Features Layer (`docs/features/`)

Per-feature documentation generated by `/add-feature` workflow.

| File | Purpose | Generated By |
|------|---------|--------------|
| `requirements.md` | User stories, acceptance criteria | business-analyst |
| `impact-analysis.md` | Domain changes, risks, audit trail | business-analyst |
| `technical-design.md` | Entity, DTOs, API design | backend-architect |
| `test-cases.md` | Test plan, test cases | qa-engineer |
| `review-report.md` | Code review findings | code-reviewer |
| `security-audit.md` | Security findings | security-engineer |

## Agent Access Patterns

### Read-Heavy Agents

These agents primarily read documentation:

- **qa-engineer**: Reads `domain/business-rules.md` to derive test cases
- **security-engineer**: Reads `domain/permissions.md` to verify access controls
- **code-reviewer**: Reads `architecture/patterns.md` to verify coding standards

### Write-Heavy Agents

These agents create or update documentation:

- **business-analyst**: Maintains `domain/` files, creates `requirements.md` and `impact-analysis.md`
- **backend-architect**: Creates `architecture/` files and `features/*/technical-design.md`

## Maintenance Guidelines

1. **Entity changes**: Update `domain/entities/{entity}.md` and notify affected agents
2. **New business rule**: Add to `domain/business-rules.md` with BR-XXX format
3. **New permission**: Add to `domain/permissions.md` with role mapping
4. **New feature**: Create `features/{feature-name}/` directory via `/add-feature`
5. **Architecture change**: Update `architecture/README.md` and create ADR
